# Slime Time

2D pixel-art game in **Godot 4.7** (GDScript). A slime glides through a pitch-black maze; its goo trail reveals the map, moving drains the slime meter, and a golden chalice is the exit of every story level (the randomizer's goal is a gold ticket voucher instead). Original spec and build phases (partly superseded, marked as such): [docs/game-design.md](docs/game-design.md). Current state, launch/test/save safety, open tasks and the per-feature history: [docs/handoff.md](docs/handoff.md) (start with its 'Current state'); index of all docs: [docs/README-docs.md](docs/README-docs.md). **All 6 build phases are done** (plus the later flow, polish, randomizer, hard-mode and trail-map phases). Further work is tuning, content and polish requested by the user.

## Pixel-art rules (keep these consistent)
- Base resolution **320x180**, window 1280x720, stretch mode `viewport` + `integer` scaling.
- **16x16 tiles**; slime frames are 20x20 (≈14 px body, room to squash/stretch). Nearest-neighbor filtering is the project default; never enable texture filtering. UI text uses the generated slimy pixel font (`assets/fonts/pixel.fnt`: 5x7 glyphs with goo drips in the 2 px below the baseline; the line box is only the 7 px letter body and the 1 px letter gap sits on each glyph's left, so text centers on its letter pixels; `UIKit.LINE_SPACING` adds the drips back between lines; the baked drips are replaced on screen by `assets/shaders/text_drips.gdshader` (`UIKit.text_material()`, set on labels, buttons and the HUD), which grows random drips per letter from its screen position and a `seed` that `UIKit.text_material()` rerolls each time a screen opens (so repeated letters drip differently and revisiting a screen drips anew; letters with a lone bottom pixel such as 4, 7, i rarely drip); shaded white/grey so it tints well; project default font): size 8 for text, 16 for titles (16 px labels use the 2x copy `assets/fonts/pixel_big.fnt` via `UIKit.use_big_font`, whose letter gap is split 1 px each side so centered titles sit exactly on center). Text color follows the equipped skin via `SkinText` (`scripts/ui/skin_text.gd`): labels made with `UIKit.make_label` using GOLD/TEXT/TEXT_DIM become title/text/dim roles; rainbow cycles.
- `snap_2d_transforms_to_pixel` is on; avoid sub-pixel scaling or rotation of sprites.
- Colors come from the palette in `tools/make_placeholder_art.py` (`PAL`). New art should reuse it.

## Layout
- **Title** (`scenes/title.tscn` + `scripts/ui/title.gd`, the main scene, `UIKit.TITLE_SCENE`): the gooey logo in the skin's colors, the slime on either side (in its hat), an ENTER THE HUB button (PLAY on a fresh save, which goes straight to level 1 until a level is cleared) and under it the tagline ESCAPE THE FOG / OR DRY TRYING, big (16 px) on two lines; a STORY button replays the intro. On the first launch of a fresh save the wordless story intro (the launch trailer, `Story.launch_due`, checked in `title.gd`) plays automatically before the title, then a goo wipe leads into it; the finale plays once after level 10. Story text and shots: [docs/story.md](docs/story.md).
- **Hub** (`scenes/hub.tscn` + `scripts/hub.gd`, `UIKit.HUB_SCENE`: every BACK and QUIT TO HUB returns here): a round slime room seen at a slant, drawn live by `assets/shaders/hub_room.gdshader` (skin shades as uniforms; the rainbow skin recolors it into flowing hue bands) so the whole building turns, floating in the mazes' drifting banded fog; the walkable floor is an ellipse of collision segments (`FLOOR`). **Nine stations** stand evenly round the rim (`RING`, `step` = TAU / count; eight on the web, which has no trapdoor), facing the center, clockwise from the back: archway = STORY (level select), MAP TABLE = trail maps (`scenes/maps.tscn`), cauldron = UPGRADES, trapdoor = QUIT (flat; hidden on the web / `--web-ui`; asks LEAVE THE HUB? with QUIT / BACK, focus on BACK, Esc = BACK), coin bag = COIN BAG (opens a board in the room, `open_coin_board`: each story level's coins found/total; F, Esc or JUMP closes), portal = RANDOMIZER (dimmed, LOCKED until all 10 levels are beaten), gear signpost = SETTINGS, prize wheel = HAT WHEEL (`HatWheel`, `scripts/ui/hat_wheel.gd`: a wedge per hat not yet won, sized by its odds (`Hats.weight`, the rainbow hat a thin sliver at 0.3); `Progress.spin_hat` charges tickets (first spin free, then `SPIN_COST` 12 rising by 2 to 40, `spin_cost`), wins and saves before the wheel animates; `Progress.can_spin_hats()` is dev mode only while `Hats.available` is false, otherwise the prompt says COMING SOON), wardrobe = SKINS & HATS. Each station sheet has front / side (faces right, mirrored on the right) / back rows picked by where it stands (`_place_all`; view arcs `Hub.VIEW_ARC` = 35 degrees), Don't Starve style. Idle animations (`IDLE_ANIMS`) play with sounds that are louder next to the station and much softer from across the room (`station_volume`). The wheel on a stick in the middle (`rotor`) turns the whole room one station round (`turn_room`; the interact key beside it, or leaping into it; holding left turns the other way). Stations and the slime are y-sorted in `world`; footprints are AnimatableBody2D circles that move with the room. You glide/leap as your slime (skin, jelly, hat); within `USE_GAP` px of a station's footprint a goo-framed prompt at the bottom names it (ROTATE for the wheel; LOCKED / COMING SOON / a ticket price when relevant) and the interact key uses it (`interact`, F by default: made at startup by `Progress._ready`, remappable as INTERACT (HUB) in the CONTROLS page; SPACE still leaps; on a touchscreen JUMP uses a station you're right next to). A top-left pod shows the ticket balance and N/30 medals. Esc goes back to the title. `Hub.return_to` turns the room so the last station faces you. Art: `python tools/make_hub_art.py` -> `assets/sprites/hub/` (`maptable.png` included). The old menu title is kept in the `pre-hub` tag. Tests: `test_hub.gd`, `test_hub_maps.gd`, `test_hub_skins.gd`.

- **Hard mode** (`Progress.hard_mode`, checkbox on level select, saved; applies to story + randomizer): its own mazes (`Levels.HARD_SEEDS`): the slime meter is the v4 hard meter x `Levels.HARD_SLIME_MULT` (+10% per level, L1 x1.1 .. On top, distant one-off sounds `ambient_<theme>_<n>.wav` (drips, creaks, sludge burps, a faint ghostly scream, icicle drops, glass pings, crystal chimes, magma blorps...) play at random every `AMBIENT_EVENT_GAP` seconds at a random quiet level (`AMBIENT_EVENT_DB`, `AMBIENT_EVENT_TRIM`). All in `game.gd` `_start_ambience`/`_update_ambience`, following the sound on/off setting.
- `scripts/sfx.gd` — autoload `Sfx`: `Sfx.play(name, volume_db, pitch)` / `stop(name)` for the WAVs in `assets/sounds/` (generated by `python tools/make_sounds.py`); silent when `Progress.sound_on` is false.
- Shaders: `assets/shaders/fog.gdshader` (drifting noise mist, soft dithered edges, clear-in on reveal, fade layers, wall shade, glow rings; fog image is plain RGBA8 packing 16-bit last-lit and first-revealed times + a wall bit (`game._fog_color`/`_fog_decode`); float textures don't load on many phones), `slime_skin.gdshader`, `color_wheel.gdshader`.
- `assets/sprites/` — generated by `python tools/make_placeholder_art.py`: `slime_sheet.png` + `slime_sheet.json` (48 animations, built into SpriteFrames by `Slime.load_sprite_frames()`; the slime is a lit dome in six goo shades with a tinted outline, shine, eyes with glints and a soft floor shadow on grounded frames), `chalice_sheet.png` (4 frames of 16x20: polished gold lit from the left, warm brown outline, ruby band, a glint sliding along the rim; the HUD banner uses `CHALICE_FRAME`), `shadow.png`, `walls.png` (16 neighbor masks x 4 damage x 3 styles; exposed corners rounded, `CORNER_RADIUS`), `fillets.png` (16 masks: curved inner-corner pieces for floor tiles, `FILLET_RADIUS`; loaded with `load()`, not `preload`, so a fresh checkout imports cleanly), `floors.png` (8 types x 4 variants).
- itch.io images: `.\tools\promo\make_promo.ps1` renders the cover (`tools/promo/cover.tscn`, own 315x250 SubViewport → 630x500) and 5 screenshots (1280x720) to Desktop\SlimeTime-itch-images. Exports: `export_presets.cfg` (Windows Desktop, Web without threads) → `build/`.
- Generators: `tools/make_coins.py` (spinning themed coins), `tools/make_hub_art.py` (hub station sprites), `tools/make_hats.py` (hat sprites), `tools/make_theme_art.py` (themed tile atlases for levels 2-10; imports helpers from the art script), `tools/make_ui_art.py` (buttons, panels, HUD pod, icons, checkbox, slider knob → `assets/ui/`), `tools/make_placeholder_art.py` (also writes `icon.png`) (sprites/tiles), `tools/make_title.py` (the gooey `title.png` logo, drawn in goo shades so the skin shader tints it), `tools/make_font.py` (pixel font; imports the PNG writer from the art script), `tools/make_sounds.py` (wet/bubbly sound effects built from bubble pops, gloopy pitch bends and muffled noise, pitched low and dark; normalized, so set loudness with `Sfx.play` volume_db), `tools/make_ambience.py` (theme ambience loops; imports helpers from make_sounds). Rerun one after editing it, then re-import.
- `tests/` — 55 `test_*.gd` suites (each prints `RESULT: PASS`), run headless by `./tools/test_all.sh` (`suites: N failed: 0`); `test_phase1-6.gd` are the original build-phase checks (phase 3 plays all 10 levels with the autopilot; phase 5 covers skins, controls, lockstep fade, randomizer completability, menus). ## Commands on macOS / Linux (bash, from project root)
The user also works on a MacBook Pro. There, use the `.sh` twins of the PowerShell tools (same flags in `--lower-case` form) and `python3` for the generators:
- Godot: `./tools/godot.sh ...` (finds `/Applications/Godot.app`, or set `GODOT=/path/to/Godot`); Godot must be **4.7.2**, matching the project.
- Re-import: `./tools/godot.sh --path . --headless --import`
- One test: `./tools/godot.sh --path . --headless --fixed-fps 60 --quit-after 300000 -s res://tests/test_phase5.gd`; every suite: `./tools/test_all.sh`
- Screenshot: `./tools/screenshot.sh [--frames 30] [--scene res://tests/demo.tscn] [--level N] [--unlock-all --skin=custom ...]` -> `.screens/latest.png`
- Launch for the user (in the background): "launch" = `./tools/play.sh`, "dev mode" = `./tools/play.sh --dev`, a demo = `./tools/play.sh --dev --scene res://tests/demo_record_run.tscn` (no right-monitor / no-focus trick on the Mac). Options: `./tools/play.sh [--dev] [--story] [--autoplay [--speed=N]] [--scene ...] [other game flags]`.
- Launch modes: `--dev` = dev mode (everything unlocked, nothing saved; in a level **F1 = FULL BRIGHT**, **F2 = NO DRAIN**, i.e. fn+F1 / fn+F2 on a Mac, also in the pause menu's DEV panel; a run that used either earns no medal, record or tickets). `--story` = postgame test state (story beaten on normal AND hard, all 165 coins, none spent, nothing saved, the real save never read). `--autoplay [--speed=N]` = the game plays the whole story by itself (F10 / fn+F10 or Esc > QUIT TO HUB stops it and hands you control; nothing saved). Windows: `-Dev`, `-Story`, `-Autoplay`.
- **Save safety:** only a plain launch (no debug flags) reads and writes the real `user://save.cfg`. Tests, tools, headless, movie, screenshot and dev runs write to a per-process throwaway file (dev/headless/movie runs may read the real save, never write it); `--story` and `--autoplay` start from a clean in-memory state and never touch it; several flags (`--skin`, `--hard`, ...) also turn saving off. **Fresh-start policy** ([docs/itch-release.md](docs/itch-release.md)): `user://` is the release dir `custom_user_dir_name="SlimeTime_R1"`, so the real save is `~/Library/Application Support/SlimeTime_R1/save.cfg` on macOS (`%APPDATA%\SlimeTime_R1\save.cfg` on Windows, `/userfs/SlimeTime_R1/save.cfg` on the web); the pre-release save (`~/Library/Application Support/Godot/app_userdata/Slime Time/save.cfg`) is never read or touched. Saves and codes carry `[meta] epoch` (`Progress.RELEASE_EPOCH` = 1); without it they start fresh / are refused. Real-save md5 checks: compare the new path (and the old one, which must stay byte-identical).
- Exports need Godot's 4.7.2 export templates (Editor > Manage Export Templates): `./tools/godot.sh --path . --headless --export-release "Web" build/web/index.html`; zip `build/web/*` for itch.

## Workflow
- Launching for the user to play: always use `.\tools\play.ps1` (run in the background) - it opens the window centered on their right-most monitor from the first frame and without taking focus, so their borderless-fullscreen game on the other screen stays in front until they click over. "Launch" = their real save: `.\tools\play.ps1`; "dev mode" = everything unlocked, nothing saved: `.\tools\play.ps1 -Dev`; a demo: `.\tools\play.ps1 -Dev -Scene res://tests/demo_record_run.tscn`; also `-Story` and `-Autoplay [-Speed N] [-Cinematics]`. Don't launch with godot.ps1 directly (that window grabs focus on the main monitor). `tools/screenshot.ps1` uses the same quiet window (`tools/quiet_window.ps1`: `--position` + a temporary `override.cfg` with `no_focus`, which the game deletes on start via `--quiet-window`).
- After gameplay or visual changes: run the tests and take a screenshot to confirm before reporting done.
- Screenshots shown to the user (and itch promo shots) put each level's own skin on the slime: its first-run skin (Lime L1 Dark Dungeon, Mint L2 Mossy Mines, Lemon L3 Sandstone Sanctum, Ocean L4 Sunken Shrine, Grape L5 Toxic Tunnels, Crimson L6 Creepy Catacombs, Frost L7 Frozen Fortress, Inkky L8 Obsidian Oubliette, Bubblegum L9 Crystal Caverns, Ember L10 Volcanic Vault). Rainbow may appear on any level, but then the shot must show every coin found (`--all-coins`), since rainbow can't be had with coins left.
- Don't re-render the itch promo images (`tools/promo/make_promo.ps1`) or rebuild release zips as part of normal changes; only when the user asks (e.g. "get this ready for itch"). Quick verification screenshots are fine.
- Release zips live outside the repo, on the user's Desktop (`SlimeTime-vX.Y` folders, `SlimeTime-Web-itch.zip` = the web build's files at the top level, uploaded to itch as HTML5).
- Input actions in `project.godot` `[input]`: `move_left/right/up/down` (WASD + arrows), `jump` (Space), `restart` (R), `menu` (Esc = pause / back, not remappable); `interact` (F, the hub's use key) is added at runtime by Progress. `Progress.apply_bindings()` replaces the remappable ones at startup.
- In canvas_item shaders, fragment `COLOR` already includes the texture; pass modulate through a varying if you need it (see `slime_skin.gdshader`).
- The Godot editor may be open and rewrites `project.godot` in its own format; keep edits compatible.
- Write files as UTF-8 without BOM (PowerShell's `Set-Content -Encoding utf8` adds one).
- Commit working states with git so changes can be rolled back.
- Agent team (`.claude/agents/`): `gameplay-dev` (sonnet) implements code, scene, UI and shader changes and verifies with tests + a screenshot; `qa-tester` (haiku) runs suites/screenshots and reports only; `code-reviewer` (opus) read-only diff review; `game-advisor` (opus) research reports in `docs/advisor/`; `perf-profiler` (opus) measures and proposes, reports only (`docs/perf/`); `mad-hatter` (opus) hat art direction.
- Performance (see `docs/perf/`): deterministic story/hard mazes, tile sets and menu-backdrop cells are cached and callers get deep copies; fog bookkeeping runs on raw bytes with exact disc spans and holds back uploads that can't change the fog; maze BFS uses arrays; shaders skip provably unused work and avoid run-time-indexed arrays (they fail on many Android GPUs in WebGL; use `bayer4()` style functions); the rainbow UI re-themes once per frame. Optimizations must keep output pixel-identical.

# Dry Trying

**Dry Trying** (renamed 2026-10-19 by the owner; formerly Slime Time; the repo, folders, internal names, the save dir `SlimeTime_R1` and the `SLIME2-` code prefix keep the old name on purpose) is a 2D pixel-art game in **Godot 4.7.2** (GDScript, `gl_compatibility`). A slime glides through a pitch-black maze; its goo trail reveals the map, moving drains the slime meter, and a golden chalice is the exit of every story level (the randomizer's goal is a gold ticket voucher instead). 10 story levels, hard mode, randomizer, skins (opaque = normal-mode unlocks and the default look, see-through jelly = the hard-mode reward, D14), DESCENT runs, hard-mode HEAT, trail maps, hats, a ticket store; localization into English + 17 languages (D15, behind a test gate, OFF by default); save version 6. All original build phases are done; further work is tuning, content, polish and platform ports requested by the user.

Docs: current state, launch/test/save safety, open tasks: [docs/handoff.md](docs/handoff.md) (start with 'Current state'); code layout and conventions in detail: [docs/architecture.md](docs/architecture.md); UI layout rules (spacing, sizes, touch targets; the numbers are `UIKit` constants in `scripts/ui/ui_kit.gd`): [docs/ui-rules.md](docs/ui-rules.md); the 2026-10 spring cleaning (decisions D1-D16, phase reports): [docs/spring-cleaning/](docs/spring-cleaning/); localization (plan, fonts, style guide, glossaries per locale, review findings): [docs/i18n/](docs/i18n/plan.md); tutorial design and API: [docs/tutorial/design.md](docs/tutorial/design.md); index of everything: [docs/README-docs.md](docs/README-docs.md). Old reports are in `docs/archive/`.

## Pixel-art rules (keep these consistent)
- Base resolution **320x180**, window 1280x720, stretch mode `viewport` + `integer` scaling.
- **16x16 tiles**; slime frames are 20x20 (≈14 px body, room to squash/stretch). Nearest-neighbor filtering is the project default; never enable texture filtering. UI text uses the generated slimy pixel font (`assets/fonts/pixel.fnt`, 5x7 glyphs, size 8 for text, 16 for titles via `pixel_big.fnt` / `UIKit.use_big_font`; drips come from `assets/shaders/text_drips.gdshader` via `UIKit.text_material()`). Details of the font, centering and drip rules: [docs/architecture.md](docs/architecture.md).
- `snap_2d_transforms_to_pixel` is on; avoid sub-pixel scaling or rotation of sprites.
- Colors come from the palette in `tools/make_placeholder_art.py` (`PAL`). New art should reuse it.

## Layout (short map; full notes in docs/architecture.md)
- `scenes/` (title is the main scene, then hub, level select, skins, maps, controls, key_controls, story, main = gameplay + pause menu, victory); `scripts/` (gameplay and data: `game.gd`, `slime.gd`, `progress.gd` autoload = saves/unlocks, `economy.gd`, `levels.gd`, `maze_generator.gd`, `hub.gd`, ...), `scripts/ui/` (menus, `ui_kit.gd` shared theme), `scripts/autoplay/`; `scripts/loc.gd` (`Loc`: `t` / `n` / `fill`, the only way text is translated) and the `Language` autoload (`scripts/language.gd`: locales, catalogs `locale/*.po`, fonts, RTL); `assets/` (generated by the `tools/make_*.py` scripts; the palette is `PAL` in `tools/make_placeholder_art.py`); `tests/` (112 `test_*.gd` suites, each prints `RESULT: PASS`; `demo_*.tscn` watchable scenes; `bench_*.gd`); `tools/` (launch, test, screenshot, generators, `web_shell.html`, `promo/`).
- Autoloads: `Progress` (state + save), `Sfx`, `RotateHint`, `Transition`, `PlatformEvents` (Android back = `menu`, focus loss / background pauses a running level, pad stick, last input device, `progress_event` for a future Steam backend). **Platform seam:** every web / mobile / desktop / Steam check, quit, fullscreen, touch and safe-area question goes through `Platform` in `scripts/platform.gd` (`OS.has_feature("web")` lives only there); `-- --platform=ios` previews a platform's UI on the desktop (debug builds). Details: [docs/spring-cleaning/phase5-platform.md](docs/spring-cleaning/phase5-platform.md). Tests, tools, headless and movie runs never write the real save.
- **Demo build** ([docs/demo-plan.md](docs/demo-plan.md)): one switch `Platform.is_demo()` (export feature `demo`, or the debug flag `--demo` / `play.ps1 -Demo`, on a clean in-memory save); every gate and knob (levels 1-3, hard 1, upgrade cap 2, 3 fixed random mazes, RIFLE only, SHOP / HEAT / later skins locked FULL GAME, end screen, WISHLIST hidden while `Demo.WISHLIST_URL` is empty) is in `scripts/demo.gd`. Level data lives per level in `scripts/level_data/` and is only `load()`ed; `Demo.full_only_paths()` (`tools/demo_paths.gd`) lists what a demo export leaves out. The demo marks its save (`[meta] demo`) and never writes over a full-game save.
- Platform behavior worth knowing: the hub's QUIT trapdoor exists only where `Platform.can_quit()` (desktop; 8 stations on web / iOS / Android); on iOS / Android the hub's touch pause button draws a pixel-art home icon and goes to the title (D10). Desktop remembers fullscreen (`[settings] fullscreen`). **DESCENT is switched OFF** (`Economy.DESCENT_ENABLED := false`, D11: the portal goes straight into a random maze, no resume prompt, ABYSS hidden unless owned; saved run / stats are kept, flipping the flag restores it; tests force `Economy.descent_force = 1`). When on, a Descent run is saved (`[descent_run]`) at each floor start and after each clear and offered for RESUME on relaunch; **one resume per floor** (D9), after that only QUIT RUN (banks half the pot) is offered; clearing a floor resets the count ([docs/level-design.md](docs/level-design.md) section 9).

## Commands on macOS / Linux (bash, from project root)
The user also works on a MacBook Pro. There, use the `.sh` twins of the PowerShell tools (same flags in `--lower-case` form) and `python3` for the generators:
- Godot: `./tools/godot.sh ...` (finds `/Applications/Godot.app`, or set `GODOT=/path/to/Godot`); Godot must be **4.7.2**, matching the project.
- Re-import: `./tools/godot.sh --path . --headless --import`
- One test: `./tools/godot.sh --path . --headless --fixed-fps 60 --quit-after 300000 -s res://tests/test_phase5.gd`; every suite, in parallel (about 2 min): `./tools/test_all.sh [-j N] [suite ...]` (`-j N` or `JOBS=N`, default 3/4 of the cores, `-j 1` = one at a time; `JOB_TIMEOUT=sec`, default 600, kills a hung job and fails the run; `TIMES=1`, `KEEP_LOGS=dir`; suites share `tests/suite_base.gd`; each uses its own throwaway save; demo scenes and tools are explained in `tests/README.md`)
- Languages (D15): `./tools/play.sh --dev --languages` (gate `Economy.LANGUAGES_TEST`, default false: saved language or OS locale), `--lang=xx` (force locale xx for this run, never saved; `--lang=pseudo` = pseudo-localization). `python3 tools/i18n_extract.py [--merge|--check]` (strings -> `locale/messages.pot` / `.po`; `--check` also verifies `LANGUAGES_ENABLED` in `tools/web_shell.html` equals `Economy.LANGUAGES_TEST`); after translation changes `python3 tools/i18n_subset_fonts.py` (needs `pip install fonttools brotli`), then re-import.
- Test flags (debug builds, all in `Progress` game args): `--nocoincatch` (coin catch is on for everyone, D16), `--nocoinreveal` (dev-only map coin reveal off, `Economy.MAP_COIN_REVEAL_TEST`), `--demo` (the demo build on a clean save; add `--save-path=user://x.cfg` to keep one), `--tutorial[=maze|hub]` (SPLASHDOWN tutorial, shipped 2026-10-18: `Economy.TUTORIAL_TEST` true, the flag replays it on a clean in-memory save; [docs/tutorial/design.md](docs/tutorial/design.md)). Always `./tools/i18n_capture.sh --gate` after text/UI changes.
- Screenshot: `./tools/screenshot.sh [--frames 30] [--scene res://tests/demo.tscn] [--level N] [--unlock-all --skin=custom ...]` -> `.screens/latest.png`
- Launch for the user (in the background): "launch" = `./tools/play.sh`, "dev mode" = `./tools/play.sh --dev`, a demo = `./tools/play.sh --dev --scene res://tests/demo_record_run.tscn` (no right-monitor / no-focus trick on the Mac). Options: `./tools/play.sh [--dev] [--story] [--autoplay [--speed=N]] [--scene ...] [other game flags]`.
- Launch modes: `--dev` = dev mode (everything unlocked, nothing saved; in a level **F1 = FULL BRIGHT**, **F2 = NO DRAIN**, i.e. fn+F1 / fn+F2 on a Mac, also in the pause menu's DEV panel; a run that used either earns no medal, record or tickets). `--story` = postgame test state (story beaten on normal AND hard, all 165 coins, none spent, nothing saved, the real save never read). `--autoplay [--speed=N]` = the game plays the whole story by itself (F10 / fn+F10 or Esc > QUIT TO HUB stops it and hands you control; nothing saved). Windows: `-Dev`, `-Story`, `-Autoplay`.
- **Save safety:** only a plain launch (no debug flags) reads and writes the real `user://save.cfg`. Tests, tools, headless, movie, screenshot and dev runs write to a per-process throwaway file (dev/headless/movie runs may read the real save, never write it); `--story` and `--autoplay` start from a clean in-memory state and never touch it; several flags (`--skin`, `--hard`, ...) also turn saving off. **Fresh-start policy** ([docs/itch-release.md](docs/itch-release.md)): `user://` is the release dir `custom_user_dir_name="SlimeTime_R1"`, so the real save is `~/Library/Application Support/SlimeTime_R1/save.cfg` on macOS (`%APPDATA%\SlimeTime_R1\save.cfg` on Windows, `/userfs/SlimeTime_R1/save.cfg` on the web); the pre-release save (`~/Library/Application Support/Godot/app_userdata/Slime Time/save.cfg`) is never read or touched. Saves and codes carry `[meta] epoch` (`Progress.RELEASE_EPOCH` = 1); without it they start fresh / are refused. Real-save md5 checks: compare the new path (and the old one, which must stay byte-identical).
- Exports need Godot's 4.7.2 export templates (Editor > Manage Export Templates): `./tools/godot.sh --path . --headless --export-release "Web" build/web/index.html`; zip `build/web/*` for itch. Presets: Windows Desktop, Web, macOS (universal, ad-hoc signed), Linux (x86_64, pck embedded -> `build/linux/DryTrying.x86_64`; Windows `build/windows/DryTrying.exe`, macOS `build/macos/DryTrying.zip`); Android / iOS / Steam are port-time work ([docs/spring-cleaning/phase5-platform.md](docs/spring-cleaning/phase5-platform.md) has the presets and the port-time checklist).

## Commands on Windows (PowerShell, from project root)
Godot isn't on PATH; `tools/godot.ps1` finds the winget-installed console binary.
- Re-import assets after adding/changing files: `.\tools\godot.ps1 --path . --headless --import`
- Smoke-run a scene for errors: `.\tools\godot.ps1 --path . --headless --quit-after 20 res://scenes/title.tscn`
- Tests (run each): `.\tools\godot.ps1 --path . --headless --fixed-fps 60 --quit-after 300000 -s res://tests/test_phase5.gd` (prints `RESULT: PASS`; `--quit-after` stops a test that errors out instead of hanging)
- Screenshot: `.\tools\screenshot.ps1 [-Frames 30] [-Scene res://tests/demo.tscn] [-Level N] [-GameArgs --unlock-all,--skin=custom,--random]` → `.screens/latest.png` (view it with Read). Each run clears `.screens/`.
- Inspect a screenshot up close: `python tools/upscale_png.py .screens/latest.png .screens/zoom.png 4 [x y w h]`

## Workflow
- Launching for the user to play: always use `.\tools\play.ps1` (run in the background) - it opens the window centered on their right-most monitor from the first frame and without taking focus, so their borderless-fullscreen game on the other screen stays in front until they click over. "Launch" = their real save: `.\tools\play.ps1`; "dev mode" = everything unlocked, nothing saved: `.\tools\play.ps1 -Dev`; a demo: `.\tools\play.ps1 -Dev -Scene res://tests/demo_record_run.tscn`; also `-Story`, `-Demo` (the demo build) and `-Autoplay [-Speed N] [-Cinematics]`. Don't launch with godot.ps1 directly (that window grabs focus on the main monitor). `tools/screenshot.ps1` uses the same quiet window (`tools/quiet_window.ps1`: `--position` + a temporary `override.cfg` with `no_focus`, which the game deletes on start via `--quiet-window`).
- After gameplay or visual changes: run the tests and take a screenshot to confirm before reporting done.
- Screenshots shown to the user (and itch promo shots) put each level's own skin on the slime: its first-run skin (Lime L1 Dark Dungeon, Mint L2 Mossy Mines, Lemon L3 Sandstone Sanctum, Ocean L4 Sunken Shrine, Grape L5 Toxic Tunnels, Crimson L6 Creepy Catacombs, Frost L7 Frozen Fortress, Inkky L8 Obsidian Oubliette, Bubblegum L9 Crystal Caverns, Ember L10 Volcanic Vault). Rainbow may appear on any level, but then the shot must show every coin found (`--all-coins`), since rainbow can't be had with coins left.
- Don't re-render the itch promo images (`tools/promo/make_promo.ps1`, on the Mac `tools/promo/make_promo.sh [--out-dir DIR]`: same file names) or rebuild release zips as part of normal changes; only when the user asks (e.g. "get this ready for itch"). Quick verification screenshots are fine.
- Release zips live outside the repo, on the user's Desktop (still the old names: `SlimeTime-vX.Y` folders, `SlimeTime-Web-itch.zip` = the web build's files at the top level, uploaded to itch as HTML5).
- Player-visible text always goes through `Loc.t(ctx, msgid, args)` / `Loc.n(...)` (never a bare string, never auto-translation) with a `# i18n:` hint comment for the translators (width budget, placeholders); `# i18n: ignore (reason)` marks text that must stay as is. `tools/i18n_extract.py --check` and the i18n tests enforce it. **English only for now (owner, 2026-10-18):** change and check English only; the other languages are brought in line after the game is finalized, only when the owner asks; after each text/UI change run `./tools/i18n_capture.sh --gate` and log it in docs/i18n/pending.md; "all languages" in a request = do every language now (see docs/NEXT-SESSION.md).
- Input actions in `project.godot` `[input]`: `move_left/right/up/down` (WASD + arrows), `jump` (Space), `restart` (R), `menu` (Esc = pause / back, not remappable); `interact` (F) and `ability_rifle` / `ability_splat` / `ability_kaze` (1 / 2 / 3) are added at runtime by Progress; abilities work ONLY in randomizer mazes and Descent (`Abilities.allowed_in`). The remappable ones are replaced at startup by `Progress.apply_bindings()` (CONTROLS page), which then adds the fixed gamepad layer (`Platform.PAD_BUTTONS`): left stick (snapped to 8 directions) / D-pad move, A leap (and menu accept), X use, B back (`ui_cancel`), START pause / back, VIEW restart, LB / Y / RB = abilities 1 / 2 / 3, LB / RB also switch tabs; glyphs and pad remapping are later work.
- In canvas_item shaders, fragment `COLOR` already includes the texture; pass modulate through a varying if you need it (see `slime_skin.gdshader`).
- The Godot editor may be open and rewrites `project.godot` in its own format; keep edits compatible.
- Write files as UTF-8 without BOM (PowerShell's `Set-Content -Encoding utf8` adds one).
- Commit working states with git so changes can be rolled back.
- Agent team (`.claude/agents/`): `gameplay-dev` implements code, scene, UI and shader changes and verifies with tests + a screenshot; `qa-tester` runs suites/screenshots and reports only; `code-reviewer` read-only diff review; `game-advisor` research reports; `perf-profiler` measures and proposes (`docs/perf/`); `mad-hatter` hat art direction; `i18n-engineer` (localization code, fonts, tooling), `localizer` (translations, glossaries), `tutorial-designer` (onboarding design and build); spring-cleaning/port agents: `code-janitor`, `docs-keeper`, `test-curator`, `asset-auditor`, `ui-polisher`, `platform-porter`.
- Performance: see [docs/architecture.md](docs/architecture.md) "Performance" and `docs/perf/`. Shaders must not use run-time-indexed arrays (they fail on many Android GPUs in WebGL; use `bayer4()` style functions). Optimizations must keep output pixel-identical. Frame rate: physics stays at 60 ticks; physics interpolation (`project.godot` `physics_interpolation`, opt-in by the slime) switches on only above ~72 fps (off below 66, `Transition.follow_frame_rate`), with a pixel-locked camera, so 60 fps output is unchanged and 120/144/240 Hz is smooth.

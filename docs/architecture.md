## Pixel-art rules (keep these consistent)
- Base resolution **320x180**, window 1280x720, stretch mode `viewport` + `integer` scaling.
- **16x16 tiles**; slime frames are 20x20 (≈14 px body, room to squash/stretch). Nearest-neighbor filtering is the project default; never enable texture filtering. UI text uses the generated slimy pixel font (`assets/fonts/pixel.fnt`: 5x7 glyphs with goo drips in the 2 px below the baseline; the line box is only the 7 px letter body and the 1 px letter gap sits on each glyph's left, so text centers on its letter pixels; `UIKit.LINE_SPACING` adds the drips back between lines; the baked drips are replaced on screen by `assets/shaders/text_drips.gdshader` (`UIKit.text_material()`, set on labels, buttons and the HUD), which grows random drips per letter from its screen position and a `seed` that `UIKit.text_material()` rerolls each time a screen opens (so repeated letters drip differently and revisiting a screen drips anew; letters with a lone bottom pixel such as 4, 7, i rarely drip); shaded white/grey so it tints well; project default font): size 8 for text, 16 for titles (16 px labels use the 2x copy `assets/fonts/pixel_big.fnt` via `UIKit.use_big_font`, whose letter gap is split 1 px each side so centered titles sit exactly on center). Text color follows the equipped skin via `SkinText` (`scripts/ui/skin_text.gd`): labels made with `UIKit.make_label` using GOLD/TEXT/TEXT_DIM become title/text/dim roles; rainbow cycles.
- `snap_2d_transforms_to_pixel` is on; avoid sub-pixel scaling or rotation of sprites.
- Colors come from the palette in `tools/make_placeholder_art.py` (`PAL`). New art should reuse it.

## Input and shaders
- Input actions in `project.godot` `[input]`: `move_left/right/up/down` (WASD + arrows), `jump` (Space), `restart` (R), `menu` (Esc = pause / back, not remappable); `interact` (F, the hub's use key) and `ability_rifle` / `ability_splat` / `ability_kaze` (1 / 2 / 3, the ticket ABILITIES; they work ONLY in randomizer mazes and Descent, off in every story level incl. hard and the hard-mode randomizer: `Abilities.allowed_in`) are added at runtime by Progress (all remappable on the CONTROLS page, two columns). `Progress.apply_bindings()` replaces the remappable ones at startup, then adds the fixed gamepad layer (`Platform.PAD_BUTTONS`: stick / D-pad move, A leap, X use, B back, START pause, VIEW restart, LB / Y / RB abilities, LB / RB tabs; the stick is snapped to 8 directions by the `PlatformEvents` autoload).
- Platform checks go through `scripts/platform.gd` (`Platform`: web / mobile / desktop / Steam, quit, fullscreen, touch, safe area, the pad table, test overrides) and the `PlatformEvents` autoload (Android back = `menu`, focus loss or background pauses a running level, the left stick driver, the last input device, `progress_event` for future achievements). Desktop remembers the fullscreen choice (`Progress.fullscreen`, follows the window mode after a 0.8 s settle); web and phones never do. Export presets: Windows Desktop, Web, macOS, Linux (Android / iOS / Steam are port-time work); details and the port-time checklist: [spring-cleaning/phase5-platform.md](spring-cleaning/phase5-platform.md).
- In canvas_item shaders, fragment `COLOR` already includes the texture; pass modulate through a varying if you need it (see `slime_skin.gdshader`).

## Performance
- Performance (see `docs/perf/`): deterministic story/hard mazes, tile sets and menu-backdrop cells are cached and callers get deep copies; fog bookkeeping runs on raw bytes with exact disc spans and holds back uploads that can't change the fog; maze BFS uses arrays; shaders skip provably unused work and avoid run-time-indexed arrays (they fail on many Android GPUs in WebGL; use `bayer4()` style functions); the rainbow UI recolors per frame without theme change signals (goo boxes redrawn, only visible buttons and labels told; `SkinText` flow path); the maze border has its own TileMapLayers (one atlas per layer keeps gameplay at about 30 draw calls); the last maze's tile fill is cached for retries; the first title preloads the hub, level and story scenes; physics interpolation is on only above 60 fps (`Transition.follow_frame_rate`; the slime opts in, `Slime.drawn_shift` for nodes placed per frame, a pixel-locked camera). Details: [spring-cleaning/phase4-perf.md](spring-cleaning/phase4-perf.md). Optimizations must keep output pixel-identical.

# Steam setup (draft)

Written 2026-10-21 (QA must-fix 2: the Steam seam). The code and the export presets are ready; the Steam app, the
GodotSteam files and the depots need the owner's Steamworks account. Nothing here is live yet.

## What is in the repo

- **`Platform.is_steam()`** is true in a build exported with the `steam` custom feature. `Platform.steam_api()` starts
  GodotSteam once (`steamInitEx()`), only in that build, and returns null without the extension or when Steam isn't
  running, so the game still runs (the store page then opens in the browser).
- **WISHLIST:** `Demo.open_wishlist()` calls `Platform.open_store_page(Demo.store_url(), Demo.steam_app_id())`. In the
  Steam build with the overlay on, that is `Steam.activateGameOverlayToStore(app_id)`: the store page opens over the
  game, already logged in, so wishlisting is one click. Otherwise it opens the URL in the browser (a new tab on the web).
  WISHLIST shows only with a store page (`Demo.WISHLIST_URL`, or the Steam page of `Demo.STEAM_APP_ID`) and never in a
  phone app. `tests/test_steam_hook.gd` checks all of it with a fake Steam object.
- **Export presets** (generated by `tools/demo_export.gd`, like the demo presets; edit only the four full presets):

  | Preset | Features | Output |
  |---|---|---|
  | Windows Steam / macOS Steam / Linux Steam | `steam` | `build/steam/<os>/DryTrying.*` |
  | Windows Steam Demo / macOS Steam Demo / Linux Steam Demo | `steam,demo` (+ the demo cut) | `build/demo/steam/<os>/DryTryingDemo.*` |

  Every non-Steam preset excludes `addons/godotsteam/*`; the Steam ones ship it. After editing a full preset run
  `./tools/godot.sh --path . --headless -s res://tools/demo_paths.gd -- --write-presets` (`test_demo_export` fails until then).

## Owner steps (in order)

1. **Pay the Steam Direct fee** ($100). It starts a 30-day wait before anything can be released, and the store page
   must show "Coming Soon" for 2 weeks before release. Next Fest February 2027: registration closes Jan 10, 2027.
2. In Steamworks, create the **base app** (Dry Trying) and its **demo app** (Steam makes the demo a child of the base
   app). Write down both app ids.
3. Put the base app's id in `scripts/demo.gd`: `const STEAM_APP_ID := <base app id>` (the demo's WISHLIST points at the
   full game's page). Leave `WISHLIST_URL` empty unless the web demo should point somewhere else.
4. **GodotSteam:** download the GDExtension build that matches Godot 4.7.2 from https://godotsteam.com (the
   "GDExtension" plugin, not the module build) and unzip it so the repo has `addons/godotsteam/` (with its
   `.gdextension` file and the Steamworks redistributables). Check that `Engine.has_singleton("Steam")` is true in a Steam export.
   GodotSteam changed `steamInitEx`'s arguments between versions: we call it with none (the app id then comes from
   Steam or `steam_appid.txt`), which every 4.x version accepts.
5. For local testing only, put a `steam_appid.txt` with the demo's (or base app's) id next to the exported binary.
   Never ship it in a depot.
6. **Depots:** one per OS for each app (Windows, macOS, Linux). Upload `build/steam/<os>/` to the base app's depots and
   `build/demo/steam/<os>/` to the demo's. Launch options: `DryTrying.exe`, `DryTrying.app` (unzip the macOS zip),
   `DryTrying.x86_64`.
7. **Steam Cloud** (Auto-Cloud, no code): roots `WinAppDataRoaming/SlimeTime_R1`, `MacAppSupport/SlimeTime_R1`,
   `LinuxXdgDataHome/SlimeTime_R1`; pattern `save.cfg` only.
8. Content survey and AI disclosure: answer honestly (the music is made in code from the game's own sounds; check where
   the 17 translations came from before they ship).
9. Store art: `build/promo/steam/` (see [marketing/README.md](marketing/README.md)).
